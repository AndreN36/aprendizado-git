# Boas Práticas com Git e GitHub

## 1. Mensagens de commit claras
Sempre escreva mensagens de commit descritivas e objetivas, explicando o que foi feito e o porquê. Isso facilita o entendimento do histórico do projeto.

## 2. Organização de branches
Utilize padrões de nomenclatura como:
- feature/nome-da-feature
- bugfix/nome-do-bug
- hotfix/nome-do-ajuste

Isso ajuda na organização e colaboração do time.

## 3. Commits pequenos e frequentes
Evite commits muito grandes. Prefira commits menores e mais frequentes para facilitar revisão e rollback, se necessário.

## 4. Atualizar a branch regularmente
Sempre mantenha sua branch atualizada com a branch principal (main ou develop) para evitar conflitos grandes.

## 5. Revisão de código (Pull Requests)
Sempre utilize Pull Requests para revisar código antes de fazer merge, garantindo qualidade e evitando erros.
